# Note de passation — 7 juillet 2026

Contexte : passage au laptop pour un voyage. Résumé de l'état du streamer pour
reprendre sans l'historique de conversation. Pendant complet côté casque :
`docs/PASSATION-2026-07-07.md` dans `frangagn/multividVR-android`
(branche `experiment/xr-composition-layers`).

## État actuel (`main`, dernier commit `31f89ab`)

- **Transcodage live** : les formats non lisibles par le casque sont transcodés
  à la volée (ffmpeg piped, fMP4). Encodeur auto-détecté NVENC/QSV/AMF/CPU.
- **Transcodage forcé** : le casque peut ajouter `?transcode=1` sur
  `/media/{id}/stream` pour forcer le transcodage d'un fichier nominalement
  lisible mais qui décode mal sur device (action « retry via transcode » côté
  casque, dans `VideoController.Error`).
- **GOP court** : `-g 60` sur tous les encodeurs (+ `-sc_threshold 0` en x264) —
  le premier fragment fMP4 sort en ~2 s au lieu de 8-10 s.
- **Seek des flux transcodés** : le casque re-ouvre l'URL avec `?t=<secondes>`
  (le serveur relance ffmpeg à ce point) et lit la durée via `/media/{id}/info`
  (ffprobe). La logique cliente est dans `ScreenManager.cs` côté casque.
- **Pairing** : durée de vie du code 15 min (constante
  `LocalApiHost.PairingCodeLifetimeMinutes`, rotation UI alignée).
- `TypedConfirmationDialog` : confirmation par saisie pour actions sensibles.
